Traditional physical ticket agencies impose logistical friction, while many conventional digital booking tools suffer from race conditions under high concurrent demand, lack flexible dynamic cabin seating topologies (1+1+1, 2+1, and 2+2 arrangements), and fail to enforce sociocultural adjacent-seat gender constraints effectively. This project aims to design and develop a modular Online Intercity Bus Ticket Purchasing System within the scope of the CEN317 Engineering Design course at Çukurova University. The primary objective of the system is to enable users to search intercity journeys, select individual seats across heterogeneous bus schematics, enforce adjacent-seat gender policies in real time, guarantee inventory consistency via an automated 5-minute seat locking countdown, and complete purchases through a verified, 3D Secure checkout workflow. Methodologically, the platform is engineered using a decoupled client-server architecture hosted in a unified GitHub repository. The backend RESTful API is developed with Node.js and Express.js, backed by a cloud-hosted document-oriented MongoDB database managed via Mongoose ODM .To eliminate overbooking and double-allocation anomalies under concurrent access, an asynchronous time-to-live (TTL) reservation locking engine releases unpurchased seats automatically after 300 seconds. On the client side, a responsive React (Vite) and Tailwind CSS Single Page Application (SPA) implements an intuitive multi-step booking funnel. Client-side state persistence is orchestrated via React Context API synchronized with browser SessionStorage, preventing form data loss during accidental page reloads. Real-time onBlur mathematical Republic of Türkiye Identity Number (T.C. Kimlik No) validation, automatic telephone input formatting under KVKK compliance, dynamic card network identification (Visa, Mastercard, Troy), and an OTPsimulated 3D Secure verification modal ensure high-fidelity transactional security. At the current interim stage of the project, approximately 65% of the overall system lifecycle has been completed. Specifically, the unified database schema, core REST endpoints for trip search and seat status polling, the full client-side passenger form engine, algorithmic T.C. validation, 3D Secure verification layer, and the digital ticket generation voucher have been implemented and verified via automated tests. During the remaining weeks leading up to the final presentation, the team will focus on full end-to-end backend database transaction integration, merging live multi-layout canvas seat topologies, integrating external SMS webhooks for real OTP dispatch, developing an administrative fleet dashboard, and conducting concurrent load stress testing. Keywords: Intercity Bus Ticketing, Dynamic Seating Topology, Seat Locking & Timeout, Concurrency Control, Algorithmic Form Validation  CONTENTS PROJECT ABSTRACT 	i CONTENTS 	ii ABBREVIATIONS AND SYMBOLS 	iii LIST OF TABLES 	iv LIST OF FIGURES 	v PROJECT INTRODUCTION 	1 RELEVANT STUDIES AND LITERATURE REVIEW 	2 PROJECT MATERIALS 	3 System Architecture and Software Stack 	3 Backend Technologies and Database Design 	3 Frontend Framework and State Synchronization 	3 Database Schema and Algorithmic Methods 	4 CURRENT STATE OF THE PROJECT 	6 FUTURE IMPROVEMENTS FOR THE PROJECT 	9 ACKNOWLEDGEMENTS 	10 REFERENCES 	10 ABOUT THE AUTHORS AND AUTHOR CONTRIBUTIONS 	11 APPENDICES 	12  ABBREVIATIONS AND SYMBOLS Abbreviation Definition / Description ACID Atomicity, Consistency, Isolation, Durability API Application Programming Interface CRUD Create, Read, Update, and Delete DBMS Database Management System DOM Document Object Model DTO Data Transfer Object ER Entity-Relationship HMR Hot Module Replacement JSON JavaScript Object Notation JWT JSON Web Token KVKK Kişisel Verilerin Korunması Kanunu (Turkish Data Protection Law) OTP One-Time Password PCI-DSS Payment Card Industry Data Security Standard PNR Passenger Name Record PRNG Pseudo-Random Number Generator REST Representational State Transfer SPA Single-Page Application ODM Object Data Modeling TC Türkiye Cumhuriyeti – Republic of Turkey TTL Time-To-Live UI / UX User Interface / User Experience  LIST OF TABLES Table 2.1. Modern passengers expect seamless, real-time digital access to intercity journeys, interactive seating layouts, and rapid checkout experiences. However, engineering an enterprise-grade bus ticketing platform presents multidimensional architectural challenges that distinguish it from standard e-commerce workflows. Unlike generic catalog purchases, a bus seat represents a highly perishable, exclusive inventory item where concurrent reservations on the exact same seat create catastrophic double-bookings. Current research and commercial applications in automated reservation systems highlight three non-trivial engineering requirements: (i) dynamic cabin topology visualization accommodating irregular 1+1+1, 2+1, and 2+2 seat arrangements while enforcing domestic sociocultural gender rules for adjacent seating; (ii) distributed, automated seat locking with time-to-live (TTL) expiration to guarantee that abandoned reservations return to inventory within exactly 300 seconds (5 minutes); and (iii) resilient client-side state synchronization that preserves entered passenger details across page reloads (F5) while verifying identity inputs mathematically prior to payment transmission. Within the scope of the CEN317 Engineering Design course, our three-member engineering team is developing the Intercity Bus Ticket Purchasing System, a full-stack web application adhering to professional software engineering paradigms. The primary objectives are to implement a robust Node.js/MongoDB backend managing concurrency, an interactive React client rendering heterogeneous seat topographies, an algorithm-backed passenger verification and payment funnel, and a resilient timeout lockdown mechanism.          +---------------------------------------------------------------------------------------------------------+ |                                   HIGH-LEVEL SYSTEM ARCHITECTURE                                  | +-------------------------------------+  REST / JSON   +-------------------------------------+      | |      FRONTEND SPA (React + Vite)    | -------------> |     BACKEND API (Node.js + Express) |      | |  - Dynamic Seating Layouts (TM2)    |                |  - Concurrency Lock Engine (TM1)    |      | |  - Passenger Forms & Logic (TM3)    | <------------- |  - 300s Expired Seat TTL Cron (TM1) |      | |  - 3D Secure Verification Layer     |  State Sync    |  - Booking & Payment Gateways (TM1) |      | |  - SessionStorage State Recovery    |                +-------------------------------------+      | +-------------------------------------+                                   |                         |                                                                           | Mongoose ODM(TLS/SSL)   |                                                                           v                         |                                                        +-------------------------------------+      |                                                        |    CLOUD NoSQL MONGODB      |            |                                                        | (trips, seats, seat_locks, bookings)|      |                                                        +-------------------------------------+      /---------+ Figure 1.1. Kleppmann (2017) emphasized that distributed resource allocation without explicit transactional isolation results in phantom reads and double-allocation anomalies. In high-concurrency ticket reservations, multiple clients frequently attempt to reserve the same inventory slot within millisecond intervals. To resolve this, systems rely on Time-To-Live (TTL) locks where temporary leases are granted to active clients while uncommitted transactions are rolled back (Bernstein et al., 2018). Sociocultural constraints in long-distance transit represent an additional layer of domain complexity. In Turkish domestic transportation, public transit regulations mandate that adjacent seats in double-seat configurations cannot be occupied by unrelated passengers of opposite genders. Traditional web forms enforce this post-submission, producing jarring error redirects. Modern user experience engineering advocates for proactive client-side constraint mapping (Garrett, 2011), disabling invalid choices before submission. Furthermore, security standards governed by the Payment Card Industry Data Security Standard (PCI-DSS, 2022) dictate that primary account numbers (PAN) and verification codes (CVV) must never be persisted in application databases. Real-time clientside Luhn checks and card network binning (identifying Visa, Mastercard, and Troy) streamline user interaction while personal data protection laws (KVKK, 2016) mandate phone and identity masking on transactional screens. Table 2.1. Backend Technologies and Database Design The backend RESTful API server is built with Node.js and Express.js (v4.21.1). Persistent transactional storage is managed using an SSL-enabled document-oriented MongoDB database managed via Mongoose ODM. Data modeling utilizes embedded documents and referenced collections to ensure high performance and flexible schema management. An automated background scheduler monitors seat_locks records, updating expired leases (elapsed > 300 seconds) from 'LOCKED' back to 'AVAILABLE'. 3.1.2. Frontend Framework and State Synchronization The client application is an advanced Single-Page Application (SPA) built with React 19, Vite v8, React Router v7, and Tailwind CSS v4. A custom global context provider (BookingContext.jsx) acts as the centralized reactive state container. State synchronization with browser SessionStorage guarantees zero data loss during accidental page refreshes (F5) or history navigations. Database Schema and Algorithmic Methods The unified
